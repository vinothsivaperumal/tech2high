5. Authentication & Authorization

5.1 Authentication Flow

Client API Database │ │ │ │──POST /auth/login──────▶│ │ │ {email, password} │──SELECT user WHERE email▶│ │ │◀────── user row ─────────│ │ │ │ │ │──bcrypt.compare() │ │ │ (12 rounds) │ │ │ │ │◀── {token: JWT} ────────│ │ │ │ │ │──GET /student/batches──▶│ │ │ Authorization: Bearer │──verifyToken(jwt) │ │ │──requireRole("student") │ │ │──query(userId)──────────▶│ │◀── {batches: [...]}─────│◀────── results ──────────│

5.2 JWT Token Structure

{
  "userId": "uuid-v4",
  "email": "user@example.com",
  "role": "student" | "trainer" | "admin",
  "iat": 1711000000,
  "exp": 1711043200  // 12 hours
}

5.3 Middleware Pipeline

Request → Helmet → CORS → Morgan → JSON Parser
       → Route Match
       → verifyToken (JWT decode → attach req.user)
       → requireRole(role) (check req.user.role)
       → Zod validate body/params
       → Route handler
       → Response

9. Security Design

9.1 Security Controls Matrix

ControlStatusImplementation
Authentication✓ ImplementedJWT + bcrypt (12 rounds)
Authorization✓ ImplementedRole-based middleware (student/trainer/admin)
Input Validation✓ ImplementedZod schemas on all endpoints
SQL Injection✓ MitigatedParameterized queries ($1, $2…)
XSS✓ MitigatedReact auto-escaping + Helmet headers
CORS✓ ConfiguredOrigin allowlist in cors()
Security Headers✓ ImplementedHelmet middleware
File Upload Validation✓ ImplementedMIME type + extension whitelist, 50 MB max
Password Storage✓ Securebcrypt with 12 salt rounds
Rate Limiting⚠ MissingRecommended: express-rate-limit
CSRF Protection⚠ MissingJWT-only (no cookies) — lower risk
Credential Encryption⚠ PartialColumn exists but encryption not applied

11. Code Review Findings

11.1 Severity: High

🔴 No Rate Limiting on Login/Register

Files: auth.ts, meta.ts

Risk: Brute-force attacks on login, DDoS on geo APIs

Fix: Add express-rate-limit middleware (e.g., 5 login attempts per minute)

🔴 Credential Passwords Not Encrypted at Rest

File: admin.ts (credentials endpoints)

Risk: If database is breached, all stored DB credentials are exposed in plaintext.

Fix: Implement AES-256-GCM encryption before INSERT, decrypt on reveal.

11.2 Severity: Medium

🟠 JWT 12-Hour Expiry Without Refresh Tokens

File: utils/jwt.ts

Risk: Stolen token valid for 12 hours. No way to revoke.

Fix: Reduce to 1h, implement refresh token rotation.

🟠 No Pagination on List Endpoints

Files: Most GET endpoints in student.ts, trainer.ts

Risk: Performance degradation with growing data.

Fix: Add ?page=1&limit=20 support with OFFSET/LIMIT.

🟠 No Graceful Shutdown Handler

File: index.ts

Risk: Database connection pool not properly drained on restart.

Fix: Add process.on('SIGTERM', () => pool.end()).

🟠 External API Calls Without Timeouts

File: meta.ts (IP geolocation)

Risk: Requests hang if external APIs are down.

Fix: Add AbortController with 3-second timeout.

11.3 Severity: Low (Code Quality)

🔵 Route Files Too Large

admin.ts (2,229 lines) should be split into domain-specific files: admin-students.ts, admin-programs.ts, admin-credentials.ts, etc.

🔵 Console.log Instead of Structured Logging

Replace console.error/console.warn with winston/pino and include request IDs for traceability.

🔵 No Frontend Error Boundaries

API failures cause white screens. Wrap dashboard roots in React Error Boundaries.

🔵 Magic Strings Repeated

Role enums like z.enum(["student", "trainer", "admin"]) repeated 20+ times. Extract to shared constants.
