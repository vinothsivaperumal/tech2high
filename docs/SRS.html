1. Introduction

1.1 Purpose

This document specifies the complete software requirements for the Tech2High Training Portal — a web-based learning management and student lifecycle platform. It covers all functional, non-functional, and interface requirements for the three user roles: Student, Trainer, and Admin.

1.2 Scope

The Tech2High Portal is a full-stack web application that enables:

  • Students to access training materials, submit assignments, build ATS-friendly resumes, view credentials, manage payments, and download professional DOCX resumes.
  • Trainers to manage batches, create assignments, upload videos, distribute materials, assign real-world projects, and track student progress.
  • Admins to manage all users, programs, courses, batches, payments, agreements, certifications, credentials, business context (clients/projects), audit logs, and IP whitelist requests.

2. Overall Description

2.1 Product Perspective

The portal is a standalone web application deployed on AWS infrastructure. It serves as the central platform for Tech2High's training operations, replacing manual spreadsheet-based tracking with an integrated digital system.

3. Functional Requirements

3.1 Authentication & User Management

FR-AUTH-01 User Registration

Priority: High   Status: Implemented

The system shall allow new users to register with email, password, full name, phone, role selection, and geolocation data (country, state, city). Geolocation shall be auto-detected from IP address and editable.

  • Passwords must be hashed with bcrypt (12 rounds)
  • Email must be unique across the system
  • Registration email notification shall be sent (if SMTP configured)
  • Input validated via Zod schema

FR-AUTH-02 User Login

Priority: High   Status: Implemented

The system shall authenticate users via email and password, returning a JWT token valid for 12 hours. Login shall be denied if is_active = false or login_enabled = false.

FR-AUTH-03 Role-Based Access Control

Priority: High   Status: Implemented

The system shall enforce three roles: Student, Trainer, Admin. Each API route group requires the corresponding role. Unauthorized access returns HTTP 403.

FR-AUTH-04 Profile Management

Priority: Medium   Status: Implemented

All authenticated users can view and update their profile: full name, phone, city, state, country, institute, experience level, date of birth, address.

FR-AUTH-05 Role-Specific Login Pages

Priority: Low   Status: Implemented

Separate login URLs for each role: /login (student), /trainer/login, /admin/login. Each redirects to role-specific dashboard upon success.

3.2 Student Features

FR-STU-01 Dashboard Overview

Priority: High   Status: Implemented

Students shall see an overview with enrolled batches count, assignment count, profile completion score (12-point scoring system), and quick-access links to Zoom meetings.

FR-STU-02 Course Access

Priority: High   Status: Implemented

Students shall access courses linked to their enrolled batches. Course content includes topics, YouTube-embedded videos, and downloadable materials (PDF, DOC, SQL, ZIP).

FR-STU-03 Assignment Submission

Priority: High   Status: Implemented

Students shall view assignments for their batches and upload submissions. Accepted file types: .sql, .py, .txt, .xls, .xlsx. Maximum file size: 50 MB. Files stored in AWS S3.

FR-STU-04 IP Whitelist Requests

Priority: Medium   Status: Implemented

Students shall request IP whitelist entries by providing IP address, port, protocol, and reason. Requests are reviewed by admin. Approved requests are automatically added to the AWS EC2 Security Group.

FR-STU-05 ATS Resume Builder

Priority: High   Status: Implemented

Students shall build ATS-friendly resumes with an interactive editor containing sections for:

  • Profile information (LinkedIn, GitHub, portfolio URL, preferred role)
  • Education history (institution, degree, field, years, grade)
  • Work experience (company, title, dates, description)
  • Skills with proficiency levels
  • Personal projects (title, description, tech stack, URL)
  • Assigned business projects (auto-included, read-only)

A live preview tab and a DOCX download tab shall be available.

FR-STU-06 DOCX Resume Download

Priority: High   Status: Implemented

Students shall generate and download DOCX resumes with choice of 5 templates:

TemplateFontStyle
ClassicTimes New RomanTraditional, centered header
ModernCalibriNavy blue accents, clean lines
MinimalArialNo borders, maximum whitespace
ExecutiveGeorgiaBold serif, larger sizing
CreativeCalibriBlue accents (#2980b9), left-aligned

Generated DOCX includes: header, contact info, summary, experience, all projects (assigned + personal), education, and skills. Each generation is logged in generated_resumes table.

FR-STU-07 Credential Access

Priority: Medium   Status: Implemented

Students shall view database credentials assigned to their batches/courses. Revealing a credential's password is audit-logged. Supported types: PostgreSQL, AWS, Snowflake, MSSQL, Other.

FR-STU-08 Payment Tracking

Priority: Medium   Status: Implemented

Students shall view their payment history with status indicators: pending, partial, paid, overdue. Amounts, due dates, and payment methods are displayed.

FR-STU-09 Agreement Management

Priority: Medium   Status: Implemented

Students shall view training agreements and digitally sign them. Status transitions: not_sent → sent → signed (or rejected/expired).

FR-STU-10 Certification Status

Priority: Low   Status: Implemented

Students shall view certification status: not_eligible → eligible → issued. Completion percentage and certificate download are available.

FR-STU-11 Assigned Business Projects

Priority: Medium   Status: Implemented

Students shall view real-world projects assigned by trainers/admins, including client name, industry, role, date range, and technologies used. These projects are auto-included in resume generation.

FR-STU-12 Notifications

Priority: Low   Status: Implemented

Students shall receive and view in-app notifications from trainers and admins. Notifications can be marked as read.

3.3 Trainer Features

FR-TRN-01 Batch Management

Priority: High   Status: Implemented

Trainers shall create batches, add students by email, set Zoom meeting links, and view batch insights (student count, assignment count, video count, material count, submission count).

FR-TRN-02 Assignment Management

Priority: High   Status: Implemented

Trainers shall create, edit, and delete assignments per batch. Each assignment has title, instructions, and optional due date. Trainers view student submissions and download submitted files.

FR-TRN-03 Video Management

Priority: High   Status: Implemented

Trainers shall upload videos to S3 and manage YouTube video links per batch. YouTube videos have title, description, and URL. S3 videos support file upload up to 50 MB.

FR-TRN-04 Material Distribution

Priority: Medium   Status: Implemented

Trainers shall create and manage course materials per batch. Materials can be file uploads (S3) or external links. Types: PDF, DOC, SQL, ZIP, Link, Other. Materials can be set as view-only or downloadable.

FR-TRN-05 Student Project Assignment

Priority: Medium   Status: Implemented

Trainers shall assign real-world projects (from the business context) to students within their batches. Assignment includes role, start/end date, and description. Students must belong to the trainer's batch.

FR-TRN-06 Batch Insights Dashboard

Priority: Medium   Status: Implemented

Trainers shall view per-batch statistics: student count, total assignments, total videos, total materials, and total submissions. Overview dashboard aggregates across all batches.

3.4 Admin Features

FR-ADM-01 User Administration

Priority: High   Status: Implemented

Admins shall manage all users: view, edit, activate/deactivate, enable/disable login, soft-delete. Admins can filter students by name, email, batch, and status. Batch enrollment (add/remove students from batches) is supported.

FR-ADM-02 Program & Course Management

Priority: High   Status: Implemented

Admins shall create programs (collections of courses) with metadata: title, code, duration, category, dates. Courses have topics and embedded YouTube videos. Programs can be linked to batches.

FR-ADM-03 Payment Administration

Priority: High   Status: Implemented

Admins shall create, update, and track student payments. Fields: amount, paid amount, status (pending/partial/paid/overdue), method, due date, paid date. Linked to batches.

FR-ADM-04 Agreement Administration

Priority: Medium   Status: Implemented

Admins shall manage training agreements: create, send, track status (not_sent → sent → signed/rejected/expired). Agreement files stored in S3.

FR-ADM-05 IP Whitelist Administration

Priority: Medium   Status: Implemented

Admins shall review, approve, or reject student IP whitelist requests. On approval, the system automatically adds the IP/port rule to the configured AWS EC2 Security Group via API. All actions are audit-logged.

FR-ADM-06 Credential Management

Priority: Medium   Status: Implemented

Admins shall create and manage database credentials (PostgreSQL, AWS, Snowflake, MSSQL, Other). Credentials have host, port, database name, username, password, region, notes, and expiry date. Credentials are assigned to batches/courses/programs for scoped access.

FR-ADM-07 Material Management

Priority: Medium   Status: Implemented

Admins shall manage course materials globally: create, edit, delete. Materials can be scoped to programs, batches, courses, or topics. Supports file upload (S3) and external links.

FR-ADM-08 Business Context Management

Priority: Medium   Status: Implemented

Admins shall manage clients (company name, industry, website) and projects (title, client, technologies, domain). Projects can be assigned to students with role, date range, and description. Assigned projects are automatically included in student resumes.

FR-ADM-09 Audit Logging

Priority: High   Status: Implemented

All sensitive operations are logged with: actor user ID, action name, entity type, entity ID, and metadata (JSONB). Admins can view paginated audit logs with filtering by action, entity type, and date range.

FR-ADM-10 Resume Administration

Priority: Low   Status: Implemented

Admins shall view and manage student resume profiles. Admin can update resume status: not_started → in_progress → submitted → approved / changes_requested. Admin notes can be attached.

FR-ADM-11 Notification System

Priority: Low   Status: Implemented

Admins shall send targeted notifications to individual users or broadcast to all users of a specific role. Notifications have subject and message body.

3.5 System Settings

FR-SET-01 Theme Customization

Priority: Low   Status: Implemented

Users shall customize UI appearance: theme color, font size (small/medium/large), sidebar position (left/right), and sidebar collapse state. Settings persist in localStorage.

7. Constraints & Assumptions

7.1 Technical Constraints

  • Single EC2 instance deployment (no load balancer)
  • Single-tenant architecture — one organization per deployment
  • AWS region: us-east-1 (hardcoded for S3 and EC2 services)
  • JWT-only authentication (no session cookies)
  • Raw SQL queries (no ORM) — requires manual query optimization
  • In-memory file processing (multer) — not streamed to S3

7.2 Business Constraints

  • Training delivery is batch-based — students must be enrolled in a batch to access content
  • One trainer per batch (primary), with optional additional trainers via batch_trainers
  • No real-time collaboration — all interactions are asynchronous
  • No payment gateway integration — payments are manually tracked by admin

7.3 Assumptions

  • Users have modern web browsers with JavaScript enabled
  • AWS services (RDS, S3, EC2) are available and properly configured
  • SMTP server is optional — system functions without email
  • Internet connectivity is required for all operations
  • Admin creates initial trainer and student accounts
